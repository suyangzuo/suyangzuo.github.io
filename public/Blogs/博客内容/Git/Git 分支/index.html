分支简介

分支的用途

Git分支是版本控制的核心能力，它通过轻量的独立提交指针设计，从根本上解决了传统开发中的协作混乱、风险不可控等核心问题。

  • 🚀 实现高效并行开发

    多人可同时在各自分支开发不同功能，互不干扰，无需等待他人工作完成；新功能开发、紧急Bug修复、版本迭代可多条时间线同步推进，大幅提升团队开发效率。

  • ️🛡️ 实现严格风险隔离

    主分支main/master始终保留稳定可上线的代码，未完成的新功能、实验性代码完全不会污染主分支；线上出现紧急问题时，可拉出独立分支快速修复，无需中断当前正在进行的新功能开发。

  • ️👥 支撑规范团队协作

    每个人的修改都在独立分支中管理，从根源上避免多人直接修改同一处代码导致的冲突问题，天然适配代码合并、审核等协作流程，让每一次修改都可追溯、可审核。

  • ️⚡ 极低的性能开销

    分支只是一个指向提交记录的指针，仅占用几十字节存储空间，几乎零开销，切换分支的本质只是移动HEAD指针，速度极快，无需复制完整代码副本。

  • ️📌 灵活的版本回溯能力

    每个分支都保留完整独立的提交历史，出现问题时可快速定位、精准回滚，不会打乱整体开发节奏；支持基于不同分支维护多个发布版本，方便对历史版本进行补丁迭代

分支的本质

分支其实就是一个指针，指向提交记录。而当前分支称为HEAD也是一个指针，指向分支。因此，切换分支其实就是在移动HEAD指针，在不同的分支之间切换，这也是为何切换分支如此之快的根本原因。

分支操作

查看分支

      
        git branch     #查看本地分支
        git branch -r  #查看远程分支
        git branch -a  #查看所有分支

分支名称前面的*表示当前分支。

除了查看分支名称外，还可以查看重要的额外信息，如：分支最近一次提交的检验码、提交说明、本地分支与远程分支的关联。 

      
        git branch -v   #查看本地分支最近一次提交的校验码、提交说明
        git branch -vv  #同上，同时查看本地分支与远程分支的关联

git branch -vv可以查看本地分支与远程分支的关联，从图中可知，bugfix分支并未与远程分支关联，需要用git push -u origin bugfix建立关联。

创建分支

  • 直接在本地创建

              
            #如果"分支名称"已存在，会弹出错误提示
            git branch 分支名称  #创建分支，但是不切换

    虽然在本地创建了bugfix分支，但是：

    • 当前分支依然是main
    • 远程分支并没有bugfix，因为尚未推送。

  • ️以远程分支创建本地分支

              
            git switch -c 本地分支名称 远程仓库名称/远程分支名称  #创建+切换

            #或者

            git branch 本地分支名称 远程仓库名称/远程分支名称  #创建
            git switch 本地分支名称  #切换

    在本地创建了一个和远程分支同步的分支feature并切换到了该分支。

切换分支

      
        git switch 分支名称
        git switch -c 分支名称  #创建分支的同时切换过去

运行命令后，当前分支变成了bugfix。

提醒

在本地创建新分支后，如果需要推送到远程仓库，则首次推送时，需要运行以下命令：

        
          #仅首次推送分支时，需要 "-u 远程仓库名称 本地分支名称" 这部分
          git push -u 远程仓库名称 本地分支名称

推送后，远程仓库也出现了bugfix分支。

修改分支名称

      
        #修改当前分支名称
        git branch -m 新名称

        #修改任意分支名称
        git branch -m 旧名称 新名称

修改本地分支名称后，远程分支名称并未变动，且二者的关联依然保留。我们往往希望本地和远程相关联的分支能够同名，操作步骤如下： 

      
        # 1. 删除远程旧名分支
        git push 远程仓库名称 --delete 远程分支旧名

        # 2. 推送本地新名分支，并且和远程同名分支建立关联
        git push -u 远程仓库名称 本地分支新名

合并分支

分支的主要功能，是为了开发其它功能或者修复bug时不影响主干；但是在功能开发完毕，或者bug修复完成后，要把成果合并到主干。不仅如此，当项目较大，由多人合作时，分支合并的情况更加复杂。 

      
        #将分支b合并到分支a ➔ 确保当前分支是a，然后合并b
        git switch a  #如当前分支已经是a，则无需切换
        git merge b   #将分支b合并到分支a

我先切换到main分支，然后将bugfix分支合并到main分支。然而，并非每次合并都像图中这么简单，根据分支的情况，一般会有两种形式的合并：快进合并和三路合并。

快进合并和三路合并的产生原因

假设有两个分支：main和feature，它们都有共同的祖先提交：初始提交。

  • 快进合并产生的原因

    在共同祖先提交初始提交的基础上，只有feature进行了后续提交，无论提交多少次，整个提交记录都是单线，这种情况下进行合并就是快进合并。

    快进合并只需要把main指针移动到和feature指针相同的位置即可，快进合并是合并中最简单、最快的一种情况，这种情况无需变基。

  • 三路合并产生的原因

    每个分支在共同祖先的基础上都有自己的独特提交，此时，整个提交树不再是一条直线，无法实现快进合并。这种情况下，我们有两种选择：

    1. 三路合并

    2. 变基

    具体做法可查看2-5章节。

三路合并与变基

  • ️三路合并

    三路是哪三路？

    三路分别是：共同祖先提交、被合并分支最近的独特提交、合并分支最近的独特提交。进行三路合并时，如果只使用git merge 被合并分支名称，会打开文本编辑器，让你填写合并提交信息。如果不想自己写，可以使用git merge 被合并分支名称 --no-edit，这样会自动填写默认的合并提交信息。

    三路合并不会改变独有提交的基础，main分支独有的提交添加了log.txt的基础初始提交没有改变，但是会生成一条额外的合并提交。

    三路合并会生成一条额外的合并提交，其默认信息为Merge branch '合并分支名称'，问题是，从这条信息你根本搞不清楚合并过来的分支到底做了哪些工作，因此，在三路合并过程中，建议不要使用--no-edit选项，而是自己填写必要的合并提交信息。

  • ️变基

              
            #变基是一种特殊的合并
            git rebase 被合并分支

    变基会改变独有提交的基础，main分支独有的提交添加了log.txt的基础变成了feature分支最新的提交添加了切换分支标题。

    变基不会生成额外的提交，其本质是找到两个分支的共同祖先，再将被合并分支插入到共同祖先与合并分支的独有提交记录之间，最终使得提交树看上去非常干净。

删除分支

      
        git branch -d 本地分支名称  #删除已合并的分支
        git branch -D 本地分支名称  #强制删除未合并的本地分支，慎用！！！
        git push origin --delete 远程分支名称  #删除远程分支
        git fetch -p  #删除本地对远程分支的引用，最后执行

不能自己删除自己

如果当前分支是bugfix，则无法删除bugfix分支，必须先切换到别的分支。

无法删除，报错信息为：无法删除正在被工作树使用的分支。

  • 未完全合并，正常删除报错

    报错信息为：

    • 错误：分支 'bugfix' 未完全合并
    • 提示：如果你确定要删除，运行 'git branch -D bugfix'
    • 提示：运行 "git config set device.forceDeleteBranch false" 可屏蔽此提示

  • ️已完全合并，正常删除

    什么是完全合并

    完全合并 = 推送到远程分支 + 合并到本地其它分支

    注意：本地其它分支不一定是主分支，也可以是别的分支。

    经过完全合并，代表此分支所做的修改在本地和远程都已经同步。

  • ️删除远程分支

    删除后，远程仓库已经没有bugfix分支了。

一次性推送所有分支

假设有多个分支要推送到远程仓库，不需要一个个切换再git push，用git push --all即可。

推送完成后，如能看到红框内的信息，代表推送成功，所有本地分支都已经成功推送到对应的远程分支。

提醒

即使本地分支与远程分支没有建立关联，甚至远程分支不存在，git push --all也能成功推送。这条命令的含义为：如果远程分支不存在，就创建一个与本地分支同名的远程分支。

注意：git push --all不会建立本地分支与远程分支的关联。因此，如果创建了新分支，并且是首次推送，强烈建议使用git push -u 远程仓库名称 本地分支名称的方式建立关联。
